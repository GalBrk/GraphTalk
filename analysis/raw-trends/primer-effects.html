The headline

Primers don’t improve graph reasoning. They swap one procedure for another.

Where the primer hands the model a shortcut it can execute reliably, accuracy jumps. Where it hands the model a shortcut it executes badly — looking up one line in a forty-line list — accuracy falls, even though the primer contains the exact answer. The three panels below are the evidence.

Effect by task and condition

Each cell is the effect of that primer against filler — a content-free preamble of the same length — so what you see is the effect of the content, not of having a preamble at all.

Read node_count and cycle_check differently. At 40 nodes their answer is always the same (“40”, “Yes”), so a deficit there measures distraction — the primer pushing the model off an answer it would otherwise get for free — not graph reasoning.

Q7 · the full density range

Where the effect lives

Only node_degree and edge_existence were run past p=0.5, and that extension changes the conclusions: on the thinking arm the degree primer’s benefit grows all the way to +53 points, while on the plain 4B model it flips sign around p=0.75.

Q4 · mechanism

The primer is retrieved, not reasoned over

On node_degree the degree primer states the answer word for word. The primer lists nodes in id order, so the queried node’s id is its line number. If the model were reading the fact, position would not matter. It does.

The control is the finding. clustering has the identical length and format but contains no answer, and it shows no slope. So the decay is retrieval of the answer specifically, not a generic cost of a long preamble. The controls are not perfectly flat, though — filler on 1.7b-think slopes +12.1 points — so the claim is about steepness and monotonicity, not a zero slope.

Q4 · the correction that matters most

A recovery that is really a collapse

On edge_existence, raw accuracy for qwen3-1.7b appears to recover above p=0.5. It does not. The share of pairs that genuinely are edges rises with density, and the model simply starts answering “yes” to almost everything.

ppairs that are edgesraw accbalanced acc recall on non-edgessays “yes”

Every error is a false positive: recall on real edges stays at ~100% in every cell. qwen3-4b does not collapse this way (balanced 83–92), so this is a small-model failure, not an artifact of the task.

Q4 · why the small model gives up

Capitulation, and what actually triggers it

Above p=0.5 the 1.7B model stops producing reasoning on edge_existence — 238 tokens down to 48 — and emits a bare “yes”. The obvious explanations are that the prompt got too long or the task got too hard. Both are wrong.

On the right, a prompt 7.5× longer at fixed difficulty never collapses — token counts drift up. Holding prompt length fixed instead (640 edges) and varying difficulty costs the 1.7B model 34 points, and the harder cell uses more tokens, not fewer. Neither knob produces the quit.

What does is the shape of the answer. On the identical graphs where the model bails on the yes/no question, it keeps working on the integer question — 268–287 tokens — and fails honestly at 5–8%. A binary question offers a degenerate escape; an integer question does not.

And the bail is nearly optimal. Answering “yes” to every pair at p=0.85 scores 86%, because 85% of pairs really are edges. That is the best available strategy once the task is out of reach — which is exactly why raw accuracy rewards it and balanced accuracy exposes it. A capitulated model also scores as a perfect ignorer of irrelevant primers, since it has stopped reading the prompt at all. Read any robustness number next to the response length that produced it.
