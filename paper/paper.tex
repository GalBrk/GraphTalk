\begin{abstract}
Explicit structural features help graph neural networks, but it is unclear whether stating them in text helps a language model that reads a graph as text. We prepend degree, local clustering and random-walk return statistics to GraphQA's incident encoding and evaluate two Qwen3 models, with and without thinking, on $84{,}000$ paired responses. To separate better graph reading from other explanations, we compare each primer with a length control, measure what a graph-blind solver can answer from the primer alone, and check the graph claims in responses against the edges. Stated degrees give the clearest gains, but mainly by supplying the answer: from degrees alone, the solver answers degree and edge-count queries perfectly, and degrees can hurt a model that already counts accurately. Clustering and return probabilities, which state no answer, have inconsistent effects, and structure-free text also changes answers. Accuracy can also overstate graph use: a small model's correct cycle answers often cite edges that do not exist. Explicit statistics can help a language model, but mostly by giving answers away, not by improving how it reads the graph.\footnote{\url{https://github.com/GalBrk/GraphTalk}} % [setup] [bars]
\end{abstract}

\section{Introduction}
\label{sec:intro}
Graphs have long been the domain of graph neural networks (GNNs), but language models are now also asked to reason over structured data, graphs included. A GNN is routinely helped with precomputed structural features and positional encodings, which supply information that message passing may not readily recover \citep{dwivedi2022graph,rampasek2022recipe}. A language model given a graph as text receives no such help and must extract structure from node and edge descriptions itself, and it does so poorly: on the GraphQA benchmark, \citet{fatemi2023talklikeagraph} find that LLMs struggle with basic graph tasks. Whether the help a GNN receives would also help a language model, if stated in plain text beside a fixed graph encoding, has to our knowledge not been tested. We therefore ask: \emph{when a black-box language model reads a textual graph, do explicit structural statistics improve execution of graph queries?} Answering it requires care: a degree sentence can itself contain the answer to a degree query, so an accuracy gain need not indicate better use of the edges.

We test this question by placing a primer of degree, local clustering coefficients, or random-walk return probabilities before GraphQA's incident encoding (Figure~\ref{fig:prompt}). We evaluate Qwen3-1.7B and Qwen3-4B, with and without thinking, on paired graph--question prompts across six GraphQA tasks. We also test the combined statistics, a component-count sentence, and a structure-free filler; since added text alone can change a model's answers \citep{shi2023distracted}, the filler separates the effect of a primer's length from that of the statistics it states. A graph-blind solver, which never reads the edge list, gives a lower bound on what the primer makes available; paired comparisons, joint degree and neighbor-set correctness, and checks of response claims against the graph provide further evidence about how answers are obtained.

This controlled evaluation separates information a primer supplies directly from improved use of the incident encoding. Stated degrees help mainly by supplying the answer, while statistics that do not supply it change answers inconsistently.

\section{Related Work}
\label{sec:related}
\paragraph{Graph representations for LLMs.} Work on graphs for language models has largely asked how a graph should be presented. \emph{Talk like a Graph} introduces GraphQA, a set of basic tasks on generated graphs, and compares textual encodings and prompting methods; the encoding, the task and the graph's structure all change accuracy substantially \citep{fatemi2023talklikeagraph}. NLGraph poses harder problems, such as shortest paths and maximum flow, in natural language, and finds that advanced prompting helps less as problems grow more complex \citep{wang2023nlgraph}. Later work changes the input itself: GraphToken trains an encoder whose outputs a frozen LLM reads as soft graph tokens \citep{perozzi2024letyourgraph}, and \citet{das2024modality} compare describing a graph as text, through its motifs, or as an image. Closest to our question, \citet{huang2024can} ask whether, and why, structural context in a prompt helps an LLM classify the nodes of text-attributed graphs. We hold one encoding, GraphQA's incident encoding, fixed; since the encoding alone moves accuracy, our findings are specific to it. What we vary instead is a plain-text statement of named statistics, including whether a statistic supplies the queried answer.

\paragraph{Controls and response evidence.} Added context, input length, and formatting can change model answers \citep{shi2023distracted,levy2024sametask,sclar2024quantifying}. A successful partial-input baseline exposes a shortcut, but an unsuccessful one cannot exclude other shortcuts \citep{feng2019misleading}. Generated explanations may also misrepresent how an answer was reached \citep{turpin2023unfaithful}. Our filler, graph-blind solver and edge-checked claims address each concern.

\section{Method}
\label{sec:method}
\paragraph{Models and graphs.} We evaluate Qwen3-1.7B and Qwen3-4B \citep{qwen2025qwen3}, each with thinking off (P) and on (T); each model--mode pair is an \emph{arm}. We use zero-shot greedy decoding and one response per prompt (budgets in Appendix~\ref{app:audit}). Models and graphs were chosen to leave room for a primer to help: in a pilot on the published GraphQA graphs, Gemma~4 \citep{gemma4} and Qwen3-8B/14B were near ceiling without a primer on most tasks, so any gain would have been too small to detect (Appendix~\ref{app:pilot}). We therefore use smaller models on larger, $40$-node independent-edge graphs $G(n,p)$ \citep{gilbert1959random} at $p\in\{.10,.20,.35,.50\}$, extending node-degree and edge-existence tests to $p\in\{.65,.75,.85\}$. Every condition and arm receives the same $100$ graphs per task and density, allowing paired comparisons. % [setup]

\paragraph{Tasks and primers.} We retain GraphQA's incident encoding and six tasks (Figure~\ref{fig:prompt}). Four are the primary measures: node degree, connected nodes, edge count, and edge existence. The other two have constant answers, since every graph has $40$ nodes and contains a cycle, so their accuracy cannot show graph reading; Table~\ref{tab:matrix} omits them, and we use cycle-check responses only to assess the support given for a ``yes'' answer. We score connected nodes primarily by exact match of the predicted and true neighbor sets; set-F1 is a secondary measure that gives partial credit. % [setup]

Before the encoding, we place either no primer; one sentence per node stating its degree $d_v$, its local clustering coefficient $c_v=2t_v/[d_v(d_v-1)]$, where $t_v$ counts the edges among $v$'s neighbors, or its two- and three-step random-walk return probabilities $(P^k)_{vv}$ with $P_{vu}=A_{vu}/d_v$ (a truncated random-walk structural encoding, RWSE; \citealp{dwivedi2022graph,rampasek2022recipe}); or a sentence combining all three statistics. We add two controls: a sentence giving the number of connected components, and a filler that names each node without stating a statistic. The filler is similar in length to clustering but not to the other primers (Appendix Table~\ref{tab:primerlength}). A rule-based graph-blind solver tests what can be answered from the primer without the edge list; it also receives the node and edge counts but never returns them as answers.

\paragraph{Outcomes and inference.} Each response is classified as correct, wrong, or truncated. Accuracy uses all prompts as its denominator, so a response that runs out of tokens counts against the condition rather than being dropped; otherwise a primer that made hard prompts run long could look more accurate. The primary effect is the paired change in accuracy, in percentage points, against no primer and against filler on the $400$ main-sweep graphs per task (Table~\ref{tab:matrix}). We use exact McNemar tests \citep{mcnemar1947note}, bootstrap intervals over graphs, and Benjamini--Hochberg correction \citep{benjaminihochberg1995controlling} within each arm--task--control family. Cells with at least $15\%$ truncation in either condition are flagged and excluded from pooled summaries. We also report balanced accuracy for edge existence because its positive-answer rate varies with density. A non-significant effect is not evidence of no effect (detectable sizes in Appendix~\ref{app:audit}).

\paragraph{Evidence of graph use.} Because degree and neighbor-set questions target the same node, their joint correctness tests whether a degree gain accompanies correct identification of that node's neighbors. Rule-based classifiers label each response. A \emph{lookup} answer does not restate the queried node's incident line; an \emph{enumeration} restates it and lists at least five neighbors on separate lines; a \emph{conflict} response notes that its own count disagrees with the printed degree. For correct, finished cycle-check answers, we extract every closed walk the response writes out and check each step against the edge list: a \emph{real cycle} passes through three or more distinct nodes with every step an edge, an \emph{invented cycle} includes a nonexistent edge, and a closed walk of two nodes or one that retraces its steps is \emph{not a cycle}; the remaining answers name no cycle. Among those, we also identify valid arguments from edge count: a $40$-node graph with at least $40$ edges must contain a cycle.

\paragraph{Follow-up experiments.} Beyond the main sweep, three node-degree experiments with Qwen3-1.7B retest the small clustering gain that a $40$-cell screen turned up: $400$ graphs per density at all seven densities, freshly generated graphs, and graphs of $20$--$160$ nodes at fixed mean degrees $8$ and $16$, which also include Qwen3-8B (Appendix~\ref{app:pilot}). % [ddplain] [ddrep] [fixdeg17]

\section{Results}
\label{sec:results}
\subsection{What the primers make available}
\label{sec:states}
From stated degrees alone, the graph-blind solver recovers node degree directly and edge count by halving the degree sum, both with $100\%$ accuracy. Without degrees, the rule-based solver reaches at most $21.0\%$ on degree and $10.4\%$ on edge count, compared with $14.4\%$ and $3.0\%$ without a primer (Appendix Table~\ref{tab:solver}). % [bars] [blindbar]
The solver's score measures what a primer makes available, not what a model will achieve: every encoding names all $40$ nodes in its first line, yet plain 1.7B answers node count correctly on only $31.50\%$ of prompts without a primer (Appendix Table~\ref{tab:full}), and stated degrees leave every model short of the solver (Section~\ref{sec:readoff}). % [main]
The models' largest gains likewise come where the primer states the answer (Figure~\ref{fig:effects}).

\subsection{Stated degrees can help or disrupt counting}
\label{sec:readoff}
The degree primer raises node-degree accuracy by $7.5$ points for plain 1.7B and $8.8$ for thinking 1.7B, but lowers it by $6.5$ for plain 4B, whose unaided accuracy is $99.25\%$; for thinking 4B, at $97.00\%$ unaided, its $+2.5$ points are not significant (Table~\ref{tab:matrix}). % [main]
Its effect depends on the cost of counting from the incident list. Within plain 4B, it harms queries about the lowest-degree nodes and helps those about the highest-degree nodes ($-11.8$ and $+10.6$ points across seven densities); % [pdnode]
at $p=.85$, where unaided accuracy falls to $33.0\%$, it gains $27.0$ points (Appendix~\ref{app:detail}). % [flip]
Stated degrees also supply every term needed for edge count, raising plain 4B's main-sweep accuracy from $2.00\%$ to $29.25\%$, far below the solver's $100\%$. % [main]

Stated answers are not always used. Across seven densities, plain 1.7B is correct on $43\%$ of degree prompts under the degree primer, against $39\%$ without it; none of the answers the primer turns from wrong to correct at $p=.20$ and $.35$ cites the stated value. Plain 4B, by contrast, appears to look the answer up: at $p=.50$, $62\%$ of its responses answer directly and only $8\%$ list the neighbors; across densities, its wrong lookups match the degree printed one sentence away more often than chance (Appendix~\ref{app:detail}); its losses under the degree primer concentrate where the response pattern changes. % [recover] [plaincite] [route] [copyerr] [routesplit]

\subsection{Primers also change answers they do not supply}
\label{sec:side}
Filler alone flips up to $18.6\%$ of an arm's outcomes against no primer, showing that added text can matter without adding a statistic (Appendix~\ref{app:detail}). % [churn]
Clustering and RWSE mostly have smaller effects than degree (Figure~\ref{fig:effects}) and can oppose each other: on plain 4B's edge existence, clustering raises balanced accuracy by $3.0$ points while RWSE lowers it by $6.5$ (Appendix Table~\ref{tab:ee}). % [eemain]
Clustering's $3.0$-point gain on plain 1.7B degree queries is not significant in Table~\ref{tab:matrix} but replicates on unscreened graphs and a fresh seed; it is not detected at $p\geq.65$ or in Qwen3-8B (Appendix~\ref{app:pilot}). % [main] [ddplain] [fixdeg17]
Combining the statistics can reverse their separate effects: on plain 4B's dense degree queries, degree, clustering, and RWSE each raise accuracy ($9.3$, $11.3$, and $7.7$ points), but the combined primer lowers it by $21.3$ on the same graphs (Appendix~\ref{app:detail}). % [main] [clusthi]

The largest unflagged gain without degrees comes from the component sentence, which is identical across graphs at $p\geq.20$: it raises plain 4B's exact neighbor-set accuracy by $9.2$ points, mainly by making responses restate the queried node's incident line (Appendix~\ref{app:detail}). % [main] [comp]

\subsection{Primers in thinking mode}
\label{sec:thinkmode}\label{sec:vsthink}
Thinking mode leaves primers little to add, and primers rarely substitute for it. Thinking 4B is near ceiling on degree, neighbor sets, and edge existence; every primer changes these accuracies by at most $2.5$ points, % [null4bt]
and even across all seven densities it answers $98\%$ of node-degree prompts correctly under the degree primer, against $97\%$ without. % [recover]
Thinking 1.7B, which counts less reliably, gains from stated degrees most where counting is hardest: $+16.0$ points across seven densities and $+25.7$ at $p\geq.65$. It does not simply copy the value: it still lists the neighbors in $90\%$ of responses at $p\geq.35$ and checks its count against the printed one, which raises its node-degree truncation rate from $1.1\%$ to $7.6\%$; when the two conflict, it ends with the stated value in $66\%$ of finished cases. % [verify] [trunc] [pdsource]

Nor do primers close the gap between the modes: where thinking outperforms plain mode, they rarely close it, and for plain 4B several widen it (Appendix Table~\ref{tab:vsthink}). The exceptions include the combined primer, which cuts plain 1.7B's node-degree gap from $15.8$ to $5.5$ points, and the component sentence, which brings plain 4B's neighbor-set exact match within the $\pm3$-point equivalence margin of thinking 4B. % [vsthink]

\subsection{Is a correct answer backed by the graph?}
\label{sec:reston}
Accuracy credits an answer however it was reached, so two checks ask whether correct answers rest on the edges. First, a model that reads the queried node's incident line should get both its degree and its neighbor set right. Clustering and RWSE do not significantly improve the joint correctness of degree and neighbor-set answers for the same node in any arm (Appendix~\ref{app:detail}). The degree primer raises this measure by $8.5$ points for plain 1.7B but lowers it by $9.2$ for plain 4B; the component sentence raises plain 4B's by $9.2$. % [joint]

Second, since cycle-check accuracy cannot show cycle detection (Section~\ref{sec:method}), we examine the support in correct, finished ``yes'' responses (Appendix Table~\ref{tab:cycles}). Without a primer, $43.5\%$ of plain 1.7B's correct, finished responses cite an invented cycle containing a nonexistent edge. % [ccanswer]
Counting over all prompts, valid cited cycles or edge-count arguments support $34.2\%$ and $58.5\%$ for plain 1.7B and plain 4B, respectively. % [ccvalid]
The degree primer shifts plain-model responses toward valid edge-count arguments, which need no named cycle; plain 1.7B's share of prompts with valid support rises to $50.2\%$, although its cycle-check accuracy falls by $17.5$ points as truncation rises by $8.2$. A correct ``yes'' can thus rest on a valid proof, an invented cycle, or no cycle at all. % [ccvalid] [main]

\section{Discussion}
\label{sec:discussion}
Structural statistics serve a different role here than in graph models, where random-walk encodings can distinguish structures that some message-passing networks cannot represent \citep{xu2019powerful,dwivedi2022graph}. In our setting, the incident encoding already contains every edge, but the language model must find the relevant edges and reason over them. Stated degree can bypass that computation for degree and edge-count queries, but it also introduces a lookup that can fail when the model selects the wrong node's sentence.

Clustering and RWSE, by contrast, state no answer, and their mixed effects, like those of filler and the component sentence, are consistent with primers changing how models use the prompt. Independent-edge graphs give these statistics little to convey beyond degree and density, so their behavior on graphs rich in triangles or return patterns remains open.

\subsection{Future work}
\label{sec:future}
The most direct extensions scale what we ran. Larger graphs and harder tasks, such as shortest paths \citep{wang2023nlgraph}, would restore headroom for the larger models the pilot left near ceiling, and other model families would test whether the effects are specific to Qwen3. Because the encoding alone changes accuracy \citep{fatemi2023talklikeagraph}, primers should also be crossed with GraphQA's other encodings, and more graphs per cell would detect the small side-statistic effects this design cannot. Acyclic graphs, and families that vary triangles and return patterns at matched size and density, would give cycle check two answers and let clustering and RWSE carry information.

A second direction replaces the fixed primer with interaction. An agent that queries the graph iteratively, for instance by requesting one node's neighbors at a time, would test whether stepwise access helps where a single long prompt does not. Offering the statistics as a tool the model can call would show whether a model knows when a statistic is worth computing, and when a primer is the cheapest way to supply it.

\section{Conclusion}
\label{sec:conclusion}
Do explicit structural statistics help a language model execute queries over a textual graph? In our tests, not consistently. Stated degrees gave the clearest gains, but mainly by supplying the answer: they helped where a model counted unreliably yet could use the printed value, and hurt plain 4B, which already counted accurately. Clustering and RWSE, which state no answer, had task- and density-dependent effects and never significantly improved joint degree and neighbor-set correctness, while a nearly constant component sentence produced the largest gain without stated degrees, so primers also change how a model uses the prompt. Judging a primer thus needs a graph-blind solver, a length control and graph-checked answers: a correct cycle answer can cite a nonexistent edge.

\clearpage
\section*{Limitations}
\begin{itemize}\setlength{\itemsep}{0pt}
\item \textbf{Scope.} We test two Qwen3 models (Qwen3-8B in one follow-up), one incident encoding, fixed prompts, and mostly $40$-node independent-edge graphs.
\item \textbf{Cycle check.} All sampled graphs contain cycles, so cycle analysis evaluates support for ``yes'' answers, not cycle discrimination.
\item \textbf{Controls.} The filler only roughly matches clustering's length, and component count supplies structural information. We did not test an instruction-only control; the queried node's list position and identifier length are confounded with each other.
\item \textbf{Graph-blind solver.} A solver that fails to recover an answer cannot exclude other clues in the primer.
\item \textbf{Truncation.} Fixed budgets cause substantial truncation in some thinking-mode cells, and reruns can differ.
\item \textbf{Response categories.} They describe behavior, not internal computation: only conflict classifiers were checked against blind hand labels; the others received supervised spot checks.
\end{itemize}

\section{Method Details}
\label{app:audit}

\paragraph{Primer statistics.} For the undirected adjacency matrix $A$, let $d_v=\sum_u A_{vu}$ and $P_{vu}=A_{vu}/d_v$ when $d_v>0$ (a zero row otherwise). If $t_v$ is the number of edges among $v$'s neighbors, local clustering is $c_v=2t_v/[d_v(d_v-1)]$, set to zero for $d_v<2$. The two return features are $r_v^{(k)}=(P^k)_{vv}$ for $k\in\{2,3\}$. Floats are printed to two decimals, with one sentence per node in node order (Table~\ref{tab:primerlength}).

\paragraph{Feature choice.} Degree and random-walk encodings are used in graph Transformers \citep{rampasek2022recipe}; clustering records edges among a node's neighbors. We use return steps 2 and 3: step 1 is zero in a simple graph, while step 3 reflects triangles. We omit Laplacian coordinates because their signs and degenerate eigenspace bases require a convention \citep{dwivedi2022graph}. Component count is a global control, though it is informative in principle: a graph with $n$ nodes, $m$ edges and $c$ components is acyclic exactly when $m=n-c$.

\paragraph{Models, budgets and inference.} We run the Qwen3 checkpoints with \texttt{transformers}. The output limit is $8{,}192$ tokens, except $2{,}048$ for plain arms at $p\geq.65$; the shorter limit costs little, because, pooled over primers, no arm and task in the high-density extension truncates more than $2.5\%$. % [setup] [extract]
Because Table~\ref{tab:matrix} compares $400$ paired graphs, its non-significant cells rule out only moderate gains: the median detectable gain is $5.7$ points in the 1.7B arms and $3.2$ in the 4B arms, and $18$ of thinking 4B's $28$ null comparisons sit too close to ceiling for any gain to be detectable. % [lmde]
A single $100$-graph density cell needs $7.4$ points, and side statistics (primers that do not state the queried answer) need $13.7$ at $25$--$75\%$ baseline accuracy. % [power]
The significant results survive stricter correction: under one BH correction over all $264$ tests, every bold cell of Table~\ref{tab:matrix} but one, and all but three $^{\mathrm{f}}$ marks, stay significant. % [globalbh]
Finally, even greedy decoding is not fully repeatable: rerunning $1{,}200$ identical plain-1.7B node-degree prompts changes correctness on $5.3\%$ of them. We therefore compare net correct shares, and report the number of responses that switch outcome only descriptively. % [rerun]

\paragraph{Graph-blind solver.} Besides the printed primer and the query targets, the solver sees the graph's node and edge counts (\S\ref{sec:method}), never the incident edge list. For edge count, it computes the answer from stated degrees, estimates it from mean clustering with a fitted rule, or otherwise falls back to the majority answer of the fitting graphs. Its $16$ exact rules, one heuristic and eight fitted rules are fit and scored on disjoint graphs. Fitted rules can fail outside their range: one RWSE rule infers density from return values to answer edge-existence questions, but scores below the majority answer at high density, which is why RWSE falls below no primer on that task in Table~\ref{tab:solver}. The solver's score therefore shows what one shortcut achieves, not an upper bound on what the full prompt conveys. % [bars] [leak] [rwsefit]
Sparse graphs leave strong indirect clues (\S\ref{sec:states}): from rounded clustering values alone, a separately fitted lookup answers $51.0\%$ and $54.0\%$ of degree queries at $p=.10$ and $p=.20$, against majority answers of $17.0\%$ and $16.0\%$. % [blindbar]

\paragraph{Stated answers (\S\ref{sec:readoff}).} Answer-stating primers gain most, in points, where unaided accuracy is intermediate (Table~\ref{tab:bands}; Figures~\ref{fig:degreeeffect} and~\ref{fig:headroom}). This holds when bands are formed on one half of the graphs and evaluated on the other, and at truncation thresholds from $5\%$ to $50\%$ (at least $+11.6$). % [bands] [splithalf] [bandsens]
On a log-odds scale, however, the gain is similar across the three lower bands, so the intermediate peak partly reflects the points scale; and the losses at high unaided accuracy come from plain 4B alone. % [bandlor]
Density, by contrast, has no detectable effect at a fixed unaided accuracy (in the main sweep, permutation $p=.28$ for answer-stating primers and $p=.85$ for side statistics). The one exception, a side-statistic effect on node degree that falls with density ($p=.006$), disappears once $p\geq.65$ is added ($p=.58$). % [dxbase]
Plain 4B spans both ends of Table~\ref{tab:bands}: besides its gain at $p=.85$, the degree primer costs it $12.0$ points at $p=.50$, where it answers $99.0\%$ unaided (both $q<.01$; Figure~\ref{fig:headroom}). % [flip]

\paragraph{Controls and run-to-run noise (\S\ref{sec:side}).} Filler changes $6.2$--$18.6\%$ of outcomes per arm, and the primers largely change the same questions. % [churn]
In every arm, every primer, components included, changes $38.5$--$69.1\%$ of the questions filler changes but only $3.1$--$15.2\%$ of the rest, and this gap holds within task and density ($q<.05$ for all twenty contrasts). % [overlap]
Part of this overlap is noise. When plain 1.7B's node-degree prompts are generated a second time, $24$ of $400$ questions change outcome, and every condition changes these questions more often than the rest ($q\leq.018$). However, they account for only $11$--$16$ of each condition's $65$--$113$ changes, and because each prompt was generated only twice, this undercounts how many changes noise alone causes. % [rerunflip]

On plain 4B's neighbor sets, restatements of the queried incident line are about equally accurate with the component sentence and without a primer ($95\%$ and $92\%$; $84\%$ with filler), so the sentence's gain comes mainly from restating more often. % [compproc]

How clustering helps is unclear. No sampled response explicitly invokes clustering, and the gain does not vary detectably with the queried node's coefficient ($p=.50$), though it grows with the node's degree ($p=.012$). % [rqbehaviour] [rqhetero]
The clearest pattern is list position: the gain is $+5.01$, $+0.75$ and $-0.11$ points for queried nodes in the first, middle and last list thirds, and, adjusting for degree, clustering and density, it shrinks by $1.74$ points per ten later positions ($p=.018$), while filler and component controls show no corresponding gradient. % [rqhetero]
These patterns motivate a position-based explanation but do not prove one: clustering resolves some prior copying errors while introducing others, and components and filler also reduce missed neighbors, so no clustering-specific mechanism is isolated. Shuffling node order would test the position hypothesis directly. % [rqbehaviour]
