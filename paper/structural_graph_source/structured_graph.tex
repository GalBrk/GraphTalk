\begin{abstract}
Does stating a graph's structural statistics help a language model answer queries about a graph written as text? We prepend each node's degree, local clustering or random-walk return probabilities to GraphQA's incident encoding and compare the same $40$-node graphs with and without them, for Qwen3-1.7B and Qwen3-4B with and without thinking, controlling for answer disclosure, added text and truncation. Stating the answer helps models that cannot compute it ($+7.5$ and $+8.8$ points on node degree) and costs one that can ($-6.5$); the models look the value up or check it, and the same values in a longer primer can cost accuracy. Other statistics have smaller effects whose sign depends on the statistic and the model; where structure-free text lowers accuracy, clustering and RWSE mostly do not, and they cut the non-edges a small model states as edges. On cycle detection only about a third of the correct answers given without thinking rest on a real cycle. % [main] [ccanswer]
\end{abstract}

\section{Introduction}
\label{sec:intro}
\textbf{Research question.} When a black-box language model reads a textual graph, do explicit structural statistics improve execution of graph queries? By \emph{execution} we mean computing the answer from the graph's edges.

Graph models benefit from structural encodings, and how a graph is written as text changes an LLM's accuracy on graph queries (\S\ref{sec:related}); whether a frozen LLM can use such statistics when they are written as sentences is open. A statistic can help in three ways: it can \emph{state} the answer, change the \emph{procedure} by which the model answers, or add \emph{side information} for reading the graph. We separate the three with a graph-blind solver that answers from the statement alone, a structure-free filler that measures what added text does, paired comparisons on the same graphs, truncation as its own outcome, and checks of what each correct answer rests on.

\section{Related Work}
\label{sec:related}
Structural encodings such as degree and random-walk return probabilities help trained graph models \citep{dwivedi2022graph,rampasek2022recipe}. LLM accuracy on graph queries depends on the text encoding, the task and the graph, and distracting statements lower it \citep{fatemi2023talklikeagraph,wang2023nlgraph}. Structural descriptions in prompts need not be read as topology \citep{huang2024can}, the modality and order of a graph's description change answers \citep{das2024modality,ge2025graph}, partial-input baselines expose shortcuts \citep{feng2019misleading}, and added or irrelevant text changes LLM reasoning \citep{levy2024sametask,shi2023distracted,liu2024lostinthemiddle}.

\label{sec:method}

\paragraph{Design.} Following the work above, we use GraphQA's tasks, its incident encoding (the most accurate for degree and neighbor queries) and its accuracy scoring; the statistics are the graph-learning encodings---node degree, local clustering (a normalized triangle count) and random-walk return probabilities (RWSE)---stated as sentences; the graph-blind solver is a partial-input baseline; a structure-free \emph{filler}, about as long as the clustering primer, stands for distracting text; and because order and added text change answers, we fix one layout, read every effect against both no primer and filler, and check what responses claim about the graph. Qwen3 runs the same weights with and without thinking \citep{qwen2025qwen3}, so each model is compared with its own reasoning mode. A pilot on the published GraphQA graphs ($5$--$19$ nodes) with Gemma~4 and Qwen3-8B/14B found most arms near ceiling without a primer (Appendix~\ref{app:pilot}), so the main study uses larger graphs and the smaller Qwen3-1.7B and Qwen3-4B, each in plain and thinking mode (P/T below), zero-shot.

\paragraph{Graphs, tasks and primers.} Graphs are undirected Erd\H{o}s--R\'enyi graphs \citep{gilbert1959random} with $40$ nodes at edge probabilities $p\in\{.10,.20,.35,.50\}$, and for node degree and edge existence also $\{.65,.75,.85\}$, with $100$ graphs per task and density shared by every condition and model; decoding is greedy (temperature 0), one response per prompt, capped at $8{,}192$ tokens ($2{,}048$ for the plain models' dense runs). % [setup]
The incident encoding lists each node's neighbors on its own line (``Node 3 is connected to nodes 1, 7, 12.''). We use GraphQA's six tasks: node degree, connected nodes (the queried node's neighbors), edge count, edge existence, node count and cycle check. At $40$ nodes the node count is always $40$ and every graph has a cycle, % [setup]
so those two tasks show how a prompt changes the answer rather than how the graph is read. Before the encoding we place no primer, a \emph{degree}, \emph{clustering} or \emph{RWSE} primer (return probabilities after 2 and 3 steps), or \emph{all} three, one sentence per node with values to two decimals; two diagnostics are a sentence stating the number of connected components and the filler, which names every node without any structure (``Node 0 is simply present within the graph G.''; details in Appendix~\ref{app:audit}).

\paragraph{Outcomes and analysis.} Each response is \textbf{correct}, \textbf{wrong} or \textbf{truncated} (it used the whole budget), every share has all prompts in its denominator, and an effect is the paired change in the correct share on the same graphs. Every task is scored by exact match, as in GraphQA (for connected nodes, the whole neighbor set); edge existence is also scored by balanced accuracy \citep{brodersen2010balanced}, because the share of true edges rises from $10\%$ to $85\%$ with density. % [goldshare]
Paired comparisons use exact McNemar tests \citep{mcnemar1947note}, bootstrap intervals over graphs and Benjamini--Hochberg correction within each (model, task, control) family \citep{benjaminihochberg1995controlling}; $q$ is the adjusted $p$, and we call an effect significant at $q<.05$. A graph-blind solver answers from the primer text alone (Appendix~\ref{app:audit}).
The main sweep comprises $84{,}000$ responses on $700$ graphs. % [setup]

\paragraph{Follow-up runs.} Node degree is re-tested with $400$ graphs per density for plain and thinking Qwen3-1.7B (no primer, components, clustering, degree, filler), on a fresh seed ($1{,}600$ graphs), and on a grid of $20$ to $160$ nodes at mean degree $8$ and $16$ ($400$ graphs per cell, also Qwen3-8B). % [ddplain] [ddrep] [fixdeg17]

\section{Results}
\label{sec:results}
The graph-blind solver answers node degree and edge count perfectly from the degree primer or all three statistics, by reading the queried degree or halving the sum of the stated degrees; among the other primers and tasks whose answer varies it never exceeds $74.6\%$, against $73.5\%$ with no primer, and on connected nodes $0.8\%$. % [bars]
These answer-stating cells are shaded in Table~\ref{tab:matrix}; we call every other primer--task pair side information.

\subsection{Stating the answer}
The degree primer raises node-degree accuracy for plain and thinking Qwen3-1.7B by $7.5$ and $8.8$ points ($q=.0042$, $.0008$) but costs plain Qwen3-4B, which already counts correctly, $6.5$ ($q<.001$). % [main]
Across models and densities the gain is largest where accuracy without the primer is intermediate and turns negative near ceiling (Figure~\ref{fig:headroom}); split-half estimates give the same pattern ($+13.9$, $+16.2$), so it is not regression to the mean. % [splithalf]
A model that has stopped reading the graph is not rescued: in the follow-ups on dense graphs, plain Qwen3-1.7B answers $39$ (all other nodes) on $70.8\%$ of finished answers at $p=.85$ even with the degree stated and gains $1.2$ points at $p\geq.65$, while its thinking mode gains $24.8$ (truncated $+9.0$). % [ddplain] [ddthink]

The stated value replaces or checks the model's count. Plain Qwen3-4B enumerates the queried node's neighbors in every response at $p=.50$ without a primer; with it, $62\%$ of responses read the value off, % [route]
the median response falls from $273$ to $34$ tokens, and $13$ answers break against $1$ fixed. % [flip]
When a thinking model reports a conflict between the stated value and its own count, it ends on the stated value in $93\%$ (4B) and $66\%$ (1.7B) of cases. % [pdsource]
The same values in a longer primer can cost accuracy: inside all three statistics, the degrees cost dense plain Qwen3-4B $21.3$ points ($q<.001$) where the degree primer alone gains $9.3$ ($q=.03$), % [clusthi]
and over all densities its look-ups there are right for $88.5\%$ of queried nodes 0--9 but $53.4\%$ of nodes 10--39. % [position]
On edge count the degree primer supplies the terms of the sum: plain Qwen3-4B rises from $2.00\%$ to $29.25\%$ ($+27.2$), the largest gain on a task whose answer varies. % [main] [edgecount]
Where it states only the size of the answer, on connected nodes, it raises thinking Qwen3-1.7B by $6.2$ ($q=.0079$), $3.8$ above filler ($q=.18$). % [main]

\subsection{Side information}
Effects of statistics that do not state the answer depend on the statistic and the model: on plain Qwen3-4B's edge existence clustering gains $4.0$ points and RWSE loses $10.0$ (balanced accuracy $+3.0$ and $-6.5$, $q=.018$ and $.0015$); % [main] [eemain]
on its dense node-degree queries clustering gains $11.3$ ($q<.001$). % [clusthi]
Where filler lowers accuracy---$15.8$ points on plain Qwen3-1.7B's edge existence (balanced accuracy $-10.8$), $12.5$ on plain Qwen3-4B's neighbor sets---clustering and RWSE are $19.5$ and $20.8$ points above filler on the first and $13.5$ and $12.5$ on the second (all $q<.001$); on plain Qwen3-4B's edge existence RWSE does no better than filler. % [main] [eemain]
The clearest benefit is in what plain Qwen3-1.7B claims: with a statistic it rarely states a queried non-edge as an edge ($13.7\%$ of non-edges without a primer, $2.7$--$4.4\%$ with one), % [eeclaims]
and all three statistics lower its false alarms from $0.51$ to $0.33$ over all densities % [fa]
and raise its balanced accuracy by $7.8$ points ($q=.001$), by $14.9$ on dense graphs where without a primer it answers yes to nearly every pair ($p=.0005$). % [eemain] [collapse]
The one re-tested effect, clustering on node degree for plain Qwen3-1.7B at $p\leq.50$, replicates on new graphs ($+4.0$), a fresh seed ($+4.2$), the fixed-mean-degree grid ($+6.2$) and against filler ($+3.2$, $q=.014$); on dense graphs it is absent, or a loss for thinking Qwen3-1.7B ($-5.4$, $q=.0015$), and it is absent for Qwen3-8B (Appendix Figure~\ref{fig:clustering}). % [replic] [ddrep] [fixdeg17] [ddplainfill] [ddthink] [fixdeg8] [clustarms]


\subsection{Thinking and the budget}
Thinking changes more than any statistic that does not state the answer: in the follow-ups on node degree it adds $24.8$ points to Qwen3-1.7B without a primer, % [ddgap]
and thinking Qwen3-4B, near ceiling, moves by at most $2.5$ under any primer on node degree, edge existence and neighbor sets. % [null4bt]
On edge count, thinking Qwen3-4B is right on $97.6\%$ of the answers it finishes but runs out of budget on $79.5\%$ of prompts; the component sentence's gain there ($+24.8$) is a fall in truncation ($-25.0$; Appendix Figure~\ref{fig:outcomes}). % [edgecount] [main]

\subsection{Correct is not executed}
\label{sec:executed}
Every graph has a cycle, so every correct cycle-check answer is ``yes'', and Table~\ref{tab:cycles} checks, edge by edge, what each correct answer rests on. Only $36.9\%$ of plain Qwen3-1.7B's and $34.1\%$ of plain Qwen3-4B's rest on a real cycle, and $43.5\%$ of plain Qwen3-1.7B's rest on an invented one. % [ccanswer]
Thinking raises the share resting on a real cycle to $80.9\%$ and $96.4\%$ on graphs both modes answer correctly ($q<.05$). % [ccthinktest]
With the degree primer the plain models argue instead from the number of edges, a valid argument ($55.6\%$ and $65.6\%$), % [ccanswer]
though on cycle check it costs the 1.7B models $17.5$ and $21.8$ points, mostly through truncation; % [main]
RWSE alone leads thinking Qwen3-4B to rest $42.5\%$ of its correct answers on a walk that is not a cycle (length 2 or retraced). % [ccanswer]

\section{Discussion}
\label{sec:discussion}
\paragraph{Substitution, not improvement.} Among unflagged cells on tasks whose answer varies, the largest gains come from statistics that state the answer, in the models that compute it least reliably, and a model that already counts correctly loses by switching to a look-up: a primer patches weak execution rather than improving it, and its value depends on the model.

\paragraph{Findable content.} More statistics are not better: the same values in a longer primer can cost accuracy, and rounded RWSE takes only $3.30$ distinct value pairs per graph at $p=.50$ against $12.50$ distinct degrees. % [rwse]
Filler shows that layout alone changes answers (Appendix~\ref{app:more}), so a primer must be judged against structure-free text too.

\paragraph{Measuring execution.} Plain Qwen3-1.7B's raw edge-existence accuracy rises from $54\%$ to $86\%$ between $p=.50$ and $.85$ as its balanced accuracy falls to $0.53$, near always answering yes, % [fillerdens] [collapse]
and set-F1 moves with exact match in only $3$ of $5$ large contrasts (finished pairs). % [f1]

\section{Future Work}
\label{sec:future}
\paragraph{Controlled follow-ups.} First, test whether a primer still helps when it cannot directly disclose the answer: omit queried-node values while preserving equivalent statistics for other nodes, and ask multi-step queries that require the incident edges. Second, randomize node labels and preamble order, and compare truly token-matched neutral text under equal generation budgets; these interventions would separate positional and length effects from graph information. Third, use variable-size and deliberately cyclic/acyclic corpora with balanced edge queries, then repeat the paired design on graph families beyond Erd\H{o}s--R\'enyi. Finally, measure whether answers jointly respect $d_v=|N(v)|$ and $2|E|=\sum_v d_v$ across queries, not merely whether each answer matches in isolation. Record intermediate claims only as observable output, and test their consistency against the underlying graph; stated reasoning alone does not establish the procedure that produced a response.

Beyond these tests, our results suggest that a primer helps by doing computation the model cannot do reliably itself: stating the queried node's degree raises thinking 1.7B by $+8.8$ points on node degree and lowers plain 4B, % [main]
which already counts correctly, by $-6.5$. % [main]
This points to six broader directions.

\paragraph{Who should compute.} Compare four ways of giving a model the same structure: statistics computed in advance and placed in the prompt, graph tools the model can call, code it writes and runs, and the incident encoding alone. Varying model scale, graph size and task would show when structure should be computed for the model and when the model can work it out, a choice every system that pairs an LLM with graph data has to make.

\paragraph{Predicting primer benefit.} Our effects track two measurable quantities: how much the primer reveals about the answer, which the graph-blind solver measures, and how poorly the model does without it. A model of the effect as the primer's information gain times the model's shortfall, minus a reading cost, could be fitted across many model families and tested on held-out models. The reading cost is substantial: in the dedicated degree follow-ups, filler costs thinking 1.7B $11.4$ points at $p\ge .65$. % [ddthink]
Such a model also needs repeated sampling per query, because most primer effects sit on top of churn: in $89$ of $120$ (arm, task, primer) cells, a primer changes as many outcomes as filler does. % [churn]

\paragraph{Graphs that do not fit.} Beyond $40$ nodes the encoding itself becomes the bottleneck. Under a fixed token budget, which summary keeps the most queries answerable: statistics, sampled subgraphs, or the queried node's neighborhood?

\paragraph{Searching the primer space.} We chose four features and one wording by hand, and both matter. The plain-1.7B clustering gain is $5.01$ points on queried nodes in the first third of the node list and $-0.11$ on the last third, % [rqhetero]
and under RWSE, whose sentences state a return probability ``after 2 steps'', $42.5\%$ of thinking 4B's correct cycle-check answers rest on a walk that is not a cycle (a two-node ``cycle'' or a retraced path), against $0.0\%$ without a primer. % [ccanswer]
An automated search over feature, wording, placement and scope, scored against length-matched and shuffled-value controls on held-out graphs, would bound what any primer can achieve.

\paragraph{Trust in stated statistics.} Every primer we tested was correct. Among finished degree-primed node-degree responses that report a conflict between the stated degree and the model's own count, thinking 4B ends on the stated value in $93\%$, thinking 1.7B in $66\%$ and plain 4B in $56\%$. % [pdsource]
Primers corrupted at controlled rates would show whether models verify stated structure or copy it, which matters wherever LLMs rely on metadata that may be stale or wrong.

\paragraph{Mechanism.} With open weights, activation patching could show whether a model uses a primer's content or responds only to a longer, differently formatted prompt.

\paragraph{A controlled benchmark.} The controls this study needed could be released as a benchmark, so that future claims that structure helps LLMs face the confounds we met: a graph-blind solver that exposes answer disclosure, truncation as its own outcome, length-matched content-free text, churn-aware paired comparisons, degree-preserving rewiring that changes clustering while fixing the degree sequence, gold answers and prompt length, and checks that correct answers rest on true claims. Without a primer, $43.5\%$ of plain 1.7B's correct cycle-check answers rest on an invented cycle. % [ccanswer]

\section{Conclusion}
\label{sec:conclusion}
Explicit structural statistics raise accuracy on graph queries mainly by supplying the answer, which substitutes for execution rather than improving it: it helps models that cannot compute the answer and costs one that can. Other statistics have smaller, model-specific effects, mostly avoid the cost of structure-free text, and cut the non-edges plain Qwen3-1.7B states as edges. Because correct answers can rest on invented cycles, evaluation must check what an answer rests on, not only whether it is right.

\section*{Limitations}
We study one model family (Qwen3), $40$-node Erd\H{o}s--R\'enyi graphs, one encoding and one wording per primer, zero-shot. Node ids 0--9 are both first and single-digit, so node-level results are stated by id.

\section{Method Details and Audit Trail}

\paragraph{Statistics.} With adjacency matrix $A$ and transition matrix $P=D^{-1}A$, the per-node statistics are $d_v=\sum_u A_{vu}$, $c_v=2t_v/(d_v(d_v-1))$ and $r_v^{(k)}=(P^k)_{vv}$ for $k\in\{2,3\}$, where $t_v$ counts edges among $v$'s neighbors and $c_v=0$ when $d_v<2$. Clustering and return probabilities are printed to two decimals, one sentence per node, in node order.

\paragraph{Graph-blind solver.} It uses $16$ exact rules, $1$ heuristic and $8$ rules fitted on separate graphs. % [bars]

\section{Additional Results}
\label{app:more}
\paragraph{Presentation effects.} Filler, a preamble that adds no information and only names the nodes the encoding already lists, also changes answers: a question filler flips is flipped by a primer $38.5$--$69.1\%$ of the time, against $3.1$--$15.2\%$ of other questions. % [overlap]
Under filler, plain Qwen3-1.7B largely stops listing node ids on node count ($59.5\%\to12.2\%$ of answers), % [ncanswer]
states more non-existent edges ($+9.6$), % [eeclaims]
plain Qwen3-4B invents more neighbors ($+14.8$), % [cnset]
and thinking Qwen3-4B runs out of budget less often on edge count ($78.2\%\to65.0\%$ truncated while working), % [loop]
matching the sensitivity of LLM reasoning to added and irrelevant text \citep{levy2024sametask,shi2023distracted}. Regenerating identical prompts for plain Qwen3-1.7B on node degree changes $5.3\%$ of outcomes. % [rerun]

\paragraph{Clustering on node degree.} The gain for plain Qwen3-1.7B (Figure~\ref{fig:clustering}) falls on queried nodes with low ids ($+5.01$, $+0.75$ and $-0.11$ points by thirds over all seven densities; OLS coefficient $-1.74$ per $10$ ids, $p=.018$), where filler shows no such pattern, % [rqhetero]
and its net gain is in copying errors ($224$ corrected, $176$ introduced, all densities). % [rqbehaviour]
In the thinking mode it is $+2.5$ at low density and $-5.4$ at high ($q=.043$, $.0015$). % [ddthink]

\paragraph{Thinking.} Thinking costs $17.1$ times the tokens of the plain mode at $p=.10$ and $11.5$ times at $p=.85$. % [ddgap]
Plain models run out of budget in loops ($83.9\%$ and $89.6\%$ of their truncated responses), thinking models while still working. % [loop]

\paragraph{Reading errors.} Plain Qwen3-4B's wrong look-ups under the degree primer copy the adjacent line's degree more often than chance ($17$ vs $10.4$). % [copyerr]

and $93.0\%$ of plain Qwen3-4B's missed neighbors lie below the queried node's id, against $43\%$ by chance. % [cnsource]
